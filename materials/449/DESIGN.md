# 有限但可靠的外连接重排器

## 1. 问题与旧实现的错误

旧代码把 INNER JOIN 的结合律直接套到 LEFT JOIN：

```
(A LEFT B ON A.k=B.k) INNER C ON B.k=C.k
   --盲目结合-->
A LEFT (B INNER C ON B.k=C.k) ON A.k=B.k
```

当 A 中存在 B 无匹配的行时，原树会在 `(A LEFT B)` 产生 B 补 NULL 行，随后
INNER 的 `B.k=C.k` 因 NULL 比较为 UNKNOWN 而丢弃这些行；盲目旋转后这些补空行
被保留下来，结果 bag 多出补 NULL 行（`probe.py` 中 2 行 vs 正确的 1 行）。
旧执行器还依赖手写 `right_cols` 猜测补空列，空表直接失效，且没有三值逻辑与
WHERE。

## 3. 推导了哪些属性

1. **列来源（lineage）**：每个子树由哪些基表别名构成，纯由树形状得到。
2. **空扩展引入点**：每个 LEFT 节点的右子树别名集合 `padded_aliases`，
   这些别名在该 LEFT 无匹配时全列补 NULL。
3. **谓词对补 NULL 行是否拒绝（null rejection）**：用抽象三值逻辑求值。
   补空别名的列抽象为 `PADDED`（必为 NULL），其他列抽象为 `FREE`（可取任意
   值，**包括真实 NULL**），字面量保留具体值。在抽象域上枚举 AND/OR/NOT 的
   全部可能真值；若结果集合中不含 TRUE，则该谓词必然拒绝补空行。整个过程不读
   数据，因此不会因当前样本碰巧等值而批准变换。

关键区分：真实 NULL 与补空 NULL 都参与同一套三值逻辑，但 `IS NULL` 在补空列上
恒为 TRUE（保留补空行），`IS NOT NULL` 与任何比较在补空列上恒为 FALSE/UNKNOWN
（拒绝补空行）。WHERE 始终保留在连接之上，绝不移入 ON。

## 4. 两条已证明的变换

### R1：外-内重结合（题目公开族）

```
(X LEFT Y ON p) INNER Z ON q  ==  X INNER Z ON q LEFT Y ON p
```

**唯一条件**：INNER 的 ON 谓词 `q` 不引用 Y（被空扩展的别名）。此时补空行在
重写后仍只经过 `LEFT ... ON p`，其 NULL 不被 `q` 触及，多重性与补空行完全
保留。镜像形状 `X INNER (Y LEFT Z ON r) ON q` 在 `q` 不引用 Z 时同理。
WHERE 若存在，保持在所有连接之上，不参与 R1 的列资格判定。

### R2：LEFT 归约为 INNER

当某个 LEFT 的补空行被其**上层** INNER 的 ON 或顶层 WHERE 证明必然拒绝时，
该 LEFT 可归约为 INNER（补空行本来就会被丢弃）。归约后子树全为 INNER，方可
自由使用结合律/交换律枚举。拒绝证据不足时（如 `WHERE B.v IS NULL` 反而保留
补空行）一律不归约。

### 明确拒绝

- 不检查外连接的通用 INNER 排序规则：单独出现即拒绝，绝不据此认证外连接重排。
- `probe.py` 的 B-C 反例：R1 因 `q` 引用补空表 B 被拒绝；盲目旋转产生的计划
  永远不在认证空间内，并由双 oracle 证伪其 bag 不同。R2 在该形状上若成立也只
  归约为等价的全 INNER 计划，bag 仍为正确的 1 行。
- WHERE 下移进 ON：拒绝。

## 5. 两种规划策略与代价边界

代价只使用公开统计 `{rows, keys:{列: NDV}}`，缺失行数直接报错，绝不执行候选
来反推基数。等值连接估计
`|L| * |R| / max(NDV(L.k), NDV(R.k))`，LEFT 输出以左输入为下界、按
`|R|/NDV(R.k)` 估计扇出。

- **S1 局部保守规则（`--strategy local`）**：仅应用显式证明的 R1，保留原树。
  候选数 ≤ 2，规划开销为谓词规模的线性时间。最坏情况下退回原树，代价不劣于
  原始计划（上界 = 原计划估计代价）。在公开基准上即选到
  `A INNER C` 再 `LEFT B`，最大中间结果从 1000 降到 10。
- **S2 有界枚举（默认 `bounded`）**：在 R1/R2 打开的全 INNER 空间内枚举三表的
  左深/右深形状并做可行 ON 分配（无分配谓词的笛卡尔积形状被剔除）。三表候选
  数有常数上界（实测个位数到十几个），规划开销为常数；推广到 n 表为形状数的
  组合增长，因此本实现明确限定在三表有界空间，不宣称全局最优。

公开基准（A=100 不同键、B 每键 10 行、C 仅 1 键）实测：

- 原树首步 `A LEFT B` 输出 1000 行；
- 选中计划首步 `A INNER C` 仅输出 1 行，随后 LEFT B 输出 10 行；
- 实际最大连接中间结果 = 10 行（扫描表不计），最终 10 行 bag 与原树及 SQLite
  完全一致。

## 6. 正确性如何被验证

- `test_properties.py`：抽象空拒绝的 7 个纯逻辑单元测试。
- `test_all.py`：10 个用例（B 无匹配、C 多匹配、真实 NULL、WHERE IS NULL、
  多 ON 条件、左深/右深、OR/NOT 三值逻辑等）上，真实执行器、朴素 oracle、
  SQLite 三者 bag 全等；所有认证候选逐一过双 oracle；非法形状被证伪且不在
  认证空间；基准中间结果 ≤ 10；缺统计时拒绝猜测。
- `test_random.py`：200 组随机三表（含空表、重复键、NULL）与随机树，903 个
  认证候选全部与双 oracle 一致；盲目旋转从未被认证，并在 67 组实例上被实测出
  不同 bag。
- `probe.py`：保留原 B-C 反例语义，断言 R1 被拒、盲目旋转不被认证且 bag 不同、
  选中计划与原 bag 相同。
